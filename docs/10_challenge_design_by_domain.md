# 분야별 문제 기획 — Cyber Range 공방 챌린지

> Red↔Blue 균형 출제. 각 문제는 **공격 과제(Red)**와 **방어 과제(Blue)**를 함께 정의한다.
> 이 문서는 각 분야 출제 에이전트(C1~C6)가 실제 문제를 만들 때의 기획 틀 + 예시 문제 세트.
> 문제는 기존 디지털 트윈/SIEM 위에 탑재하거나 독립 챌린지로 배포한다.

---

## 0. 공통 문제 포맷 (C0 표준)

```yaml
challenge:
  id: "WEB-001"
  title: "..."
  category: "web|forensics|detection|ai|reversing|network"
  difficulty: "easy|medium|hard|insane"
  points: { red: 100, blue: 100 }     # 공격/방어 배점
  asset: "ground_station|..."          # 연동 트윈(있으면)
  red_task:                            # 공격 과제
    goal: "..."                        # 무엇을 달성하면 성공
    flag_format: "flag{...}"
    hints: [ { cost: 10, text: "..." } ]
  blue_task:                           # 방어 과제
    goal: "..."                        # 탐지/차단/패치 중 무엇
    success_criteria: "..."            # 자동 판정 기준
  scoring:
    red_verify: "flag_match|event"     # 채점 방식
    blue_verify: "safe_probe|alert|patch_check"
  artifacts: [ "..." ]                 # 제공 파일(이미지/pcap/바이너리)
  writeup: "해설(정답 공개용, 훈련 후)"
  safety: "더미 데이터 확인, 격리 요구사항"
```

**난이도 곡선**: easy(개념 확인) → medium(응용) → hard(다단계/우회) → insane(비의도 방지된 정교한 문제). 각 분야 easy 2 / medium 3 / hard 2 / insane 1 비율 권장.

## 1. Web Security (C1)

### 출제 축
인젝션(SQL/NoSQL/Command/SSTI), 인증·세션(JWT/우회), 접근제어(IDOR/권한상승), SSRF, 역직렬화, 파일업로드, 클라이언트(XSS/CSRF), CVE 재현, 우회(403/WAF).

### 예시 문제

**WEB-001 (easy) — 텔레메트리 인젝션**
- Red: 위성 지상국 `/api/telemetry` SQLi로 users 테이블의 admin 해시 추출 → `flag{...}`.
- Blue: 해당 요청을 SIEM에서 탐지하는 Sigma 룰 작성 + 파라미터 바인딩으로 패치.
- 채점: Red=flag_match, Blue=safe_probe(patched) + 룰이 공격 트래픽에 알림.

**WEB-002 (medium) — JWT 위조**
- Red: 약한 서명키(`supersecret123`)로 admin JWT 위조 → 관리자 전용 엔드포인트 접근.
- Blue: 서명키 로테이션 + `alg:none`/약한키 탐지 룰. 위조 토큰 사용 로그 탐지.
- 개념: 하드코딩 시크릿, JWT 검증 미흡.

**WEB-003 (medium) — IDOR 체인**
- Red: `/api/mission-plan/{id}` 순차 스캔으로 타 팀 기밀 계획 유출.
- Blue: 소유권 검증 패치 + 순차 접근 패턴 탐지(임계 룰).

**WEB-004 (hard) — SSRF → 내부 피벗**
- Red: 이미지 프록시/웹훅 기능의 SSRF로 내부 메타데이터/관리 엔드포인트 접근 → 다음 단계 자격증명 획득.
- Blue: egress allowlist + SSRF 탐지(내부 IP 대역 요청 로그).
- 연계: 08 안전장치의 egress 격리와 교육적으로 연결.

**WEB-005 (hard) — 역직렬화 RCE**
- Red: Historian export의 pickle 역직렬화로 코드 실행 → 플래그 파일 read.
- Blue: JSON 전환 패치 + pickle opcode 시그니처 탐지.

**WEB-006 (insane) — WAF 우회 다단계**
- Red: 기본 WAF 룰이 켜진 상태에서 인코딩/청크/파라미터 오염으로 우회해 인젝션 성공.
- Blue: 우회를 막는 정교한 룰 재작성(정탐 유지, 정상요청 오탐 최소).
- 핵심: Red와 Blue가 같은 문제에서 룰 대 우회로 맞붙음(공방의 정수).

## 2. Forensics (C2)

### 출제 축
디스크/메모리 이미지, 파일 카빙, 타임라인, OS 아티팩트(레지스트리/prefetch/$MFT), pcap 분석, 로그 분석, 스테가노그래피, 안티포렌식 탐지.

### 예시 문제

**FOR-001 (easy) — 유출 파일 카빙**
- Red 관점 재현: 삭제된 기밀 문서를 디스크 이미지에서 복구.
- 과제(조사자): 카빙으로 `classified_dummy_report.pdf` 복구 → 내부 플래그.
- 채점: 복구 파일 해시 일치.

**FOR-002 (medium) — pcap 침해 재구성**
- 제공: 공격 세션 pcap. 과제: 공격자 IP, 익스플로잇된 엔드포인트, 유출된 데이터 3가지 특정.
- 채점: 3개 정답 필드 매칭. SIEM Discover로도 교차 검증 가능.

**FOR-003 (medium) — 메모리 포렌식**
- 제공: 메모리 덤프. 과제: 실행 중이던 악성 프로세스, C2 주소, 인젝션된 코드 영역 식별(Volatility류).
- 채점: 프로세스명 + C2 IP.

**FOR-004 (hard) — 타임라인 상관**
- 제공: 다중 소스(트윈 access log + Suricata eve + pfSense). 과제: 킬체인 시간순 재구성, 최초 침투 시각·경로·목표달성 시각 특정.
- Blue 연계: 이 재구성이 AAR의 MTTD 계산과 동일 로직 → 실전 대응 훈련.

**FOR-005 (hard) — 안티포렌식 탐지**
- 제공: 로그가 부분 삭제/타임스탬프 조작된 이미지. 과제: 조작 흔적 발견 + 원본 추정.
- 채점: 조작된 아티팩트 지목.

**FOR-006 (insane) — 스테가노 + 다단계**
- 유출 데이터가 이미지에 은닉 → 추출 → 복호 → 다음 단서. 3단 체인.

## 3. Detection Engineering / Blue (C3)

### 출제 축
SIEM 상관분석, 탐지 룰 작성(Sigma), ATT&CK 매핑, pcap 기반 탐지, 위협헌팅, 인시던트 대응.

### 예시 문제

**DET-001 (easy) — 첫 탐지 룰**
- 과제: 브루트포스(동일 src 401 연속)를 잡는 Sigma 룰 작성.
- 채점: 제공된 공격 로그셋에 알림 발생 + 정상 로그셋에 오탐 없음.

**DET-002 (medium) — 포트스캔 임계 룰**
- 과제: 수평 스캔 탐지(distinct dst.port 임계) 룰. 노이즈 섞인 데이터에서 정탐.
- 채점: 정탐율/오탐율 기준 통과.

**DET-003 (medium) — C2 비콘 헌팅**
- 과제: Zeek conn 로그에서 주기적 비콘(지터<0.1) 찾기.
- 채점: 비콘 (src,dst) 쌍 특정. (06 탐지 콘텐츠 4절 로직과 연결)

**DET-004 (hard) — 킬체인 시퀀스 룰**
- 과제: 스캔→앱공격→유출 3단 시퀀스를 하나의 상관 룰로 탐지.
- 채점: 다단계 공격에 단일 critical 알림, 개별 단계만으론 미발화.

**DET-005 (hard) — 위협헌팅 리포트**
- 제공: 대량 로그(침해 포함). 과제: 가설 기반 헌팅으로 은닉된 침해 발견 + ATT&CK 매핑 리포트.
- 채점: 발견한 기술 ID + 근거 이벤트.

**DET-006 (insane) — 오탐 지옥**
- 정교한 노이즈 속 소수 진짜 공격. 과제: 높은 정확도로 트리아지.
- 채점: 트리아지 정확도(정탐/오탐 분류).

## 4. AI Security (C4)

### 출제 축
적대적 예제(evasion), 모델 추출, 멤버십 추론, 프롬프트 인젝션/탈옥, 데이터 포이즈닝/백도어, ML 파이프라인 취약점. (Pierazzi 문제공간 프레임워크 응용)

### 예시 문제

**AI-001 (easy) — 피싱 분류기 회피 (개념)**
- 제공: 피싱 URL 탐지기(블랙박스 API). Red: 제약 없는 특징공간 변조로 오분류 유도 → 회피 성공.
- Blue: 입력 정규화/견고화로 회피 저지.
- 개념: unconstrained evasion, feature-space attack.

**AI-002 (medium) — 문제공간 제약 회피**
- Red: 실제 URL의 유효성을 유지하면서(문제공간 제약) 탐지 회피 — feature-space가 아니라 실현가능한 변형만.
- Blue: 문제공간 제약을 아는 방어(불변 특징 활용).
- 근거: Pierazzi et al. problem-space attack.

**AI-003 (medium) — 모델 추출**
- Red: 쿼리 접근만으로 대리모델 학습 → 원본 결정경계 근사 → 전이 공격.
- Blue: 쿼리 레이트리밋/워터마킹/출력 라운딩으로 추출 난이도 상승.

**AI-004 (hard) — 데이터 포이즈닝/백도어**
- Red: 학습 파이프라인에 트리거 포함 샘플 주입 → 특정 트리거에서 오작동하는 백도어 심기.
- Blue: 학습 데이터 이상 탐지 + 백도어 스캐닝(뉴런 활성 분석).

**AI-005 (hard) — 프롬프트 인젝션 (LLM 통합 서비스)**
- 대상: 대시보드의 AI 평가 기능 같은 LLM 통합 지점. Red: 간접 프롬프트 인젝션으로 시스템 지시 우회/데이터 유출.
- Blue: 입력 격리/출력 검증/권한 분리로 방어.
- 주의: 실제 LLM 통합 시 안전 경계 — 훈련용 격리 환경에서만.

**AI-006 (insane) — 적대적 견고성 공방**
- Red: 방어된 IDS/멀웨어 분류기에 대해 transferability 활용한 회피.
- Blue: adversarial training + 탐지 앙상블로 대응.
- 핵심: 04 백엔드 점수 연결로 회피 성공/방어 성공이 실시간 채점.

### AI 분야 인프라 노트
- 취약 ML 시스템은 별도 저권한 컨테이너(08 안전장치)로 격리.
- 합성 데이터셋 우선, 공개 데이터셋(EMBER 등) 사용 시 라이선스·재현성 확인.
- 모델 가중치/데이터는 더미·합성으로 실제 민감정보 배제.

## 5. Reversing / Pwn (C5)

### 출제 축
정적/동적 분석, 난독화 해제, 커스텀 인코딩(XOR 등), 바이너리 취약점(BOF/포맷스트링/힙), 펌웨어.

### 예시 문제

**REV-001 (easy) — XOR 플래그 추출**
- 제공: 플래그를 XOR로 인코딩해 검증하는 바이너리/JS. 과제: 키 복원 → 플래그.
- (기존 클리커 게임 리버싱 경험과 유사 계열)

**REV-002 (medium) — 난독화된 라이선스 체크**
- 크랙미: 난독화된 검증 루틴 분석해 유효 시리얼 도출.

**REV-003 (hard) — 스택 오버플로우 익스플로잇**
- 취약 바이너리(BOF)에서 제어흐름 탈취 → 셸/플래그.
- Blue 연계: 완화기법(스택카나리/ASLR/NX) 적용 과제.

**REV-004 (hard) — 펌웨어 분석**
- 제공: 지상국/PLC 모의 펌웨어 이미지. 과제: 추출→하드코딩 자격증명/백도어 발견.

**REV-005 (insane) — 힙 익스플로잇**
- 정교한 힙 조작. insane 난이도.

## 6. Network / OT-ICS (C6)

### 출제 축
프로토콜 분석, MITM, 피벗팅, OT 프로토콜(Modbus/S7), SCADA 공방, 방화벽 룰.

### 예시 문제

**NET-001 (easy) — 프로토콜 분석**
- pcap에서 평문 자격증명/명령 추출.

**NET-002 (medium) — 피벗팅**
- DMZ 침투 후 내부망으로 측면이동 경로 설계 → 목표 자산 도달.
- Blue: 세그멘테이션/탐지로 측면이동 차단.

**NET-003 (medium) — Modbus 조작**
- 발전소 OT: Modbus로 PLC 레지스터 미인증 쓰기 → 안전 임계 조작.
- Blue: OT 프로토콜 이상 탐지(Zeek modbus) + 인증 강제.

**NET-004 (hard) — SCADA 세이프티 우회 공방**
- Red: 다단계로 세이프티 인터록 우회(목표). Blue: 2인 승인 강제 + 우회 시도 탐지.
- 기존 트윈 PP-005와 직접 연결.

**NET-005 (hard) — 방화벽 룰 대결**
- Red: 특정 서비스 도달 경로 탐색. Blue: 최소권한 방화벽 룰로 차단하되 정상 서비스 유지.

## 7. 분야 간 크로스오버 (추천)

단일 분야보다 교육 효과가 큰 **복합 시나리오**:
- **웹→포렌식→탐지**: 웹 침해 발생 → 포렌식으로 재구성 → 탐지 룰로 재발 방지. 한 사건을 세 관점에서.
- **AI+웹**: LLM 통합 웹서비스의 프롬프트 인젝션 → 데이터 유출 → 탐지.
- **리버싱→Pwn→네트워크**: 펌웨어에서 취약점 발견 → 익스플로잇 → 네트워크 피벗.

이런 크로스오버는 05 시나리오 as-code의 다단계 킬체인으로 엮어 출제.

## 8. 출제 워크플로우 (C0~C-QA)

```
C0 표준/쿼터 배정
  └─ C1~C6 분야별 문제 초안(공통 포맷)
       └─ C-QA 검수: 재현성 / 정답 유일성 / 비의도해법 / 난이도 / 안전성 / 자동채점
            └─ 통과 → 배포 큐 → 시즌/라운드 편성
```

**C-QA 필수 체크**: ① 의도한 해법으로 풀리는가 ② unintended solution 없는가 ③ 플래그 확정적인가 ④ 실데이터/실취약점 유출 없는가 ⑤ Red·Blue 채점 자동화 동작하는가 ⑥ 난이도 표기가 실제와 맞는가.

# 팀 에이전트 역할 정의서 — Cyber Range 멀티에이전트 빌드

> Claude Code 팀 에이전트로 플랫폼을 구축·운영하기 위한 에이전트 구성.
> 성격이 다른 두 계층으로 나눔:
> - **빌드 계층(B)**: 플랫폼/인프라를 짓는 엔지니어링 에이전트
> - **콘텐츠 계층(C)**: 분야별 공방 문제를 출제하는 출제위원 에이전트
> 각 에이전트는 담당 디렉토리·인터페이스 계약·완료 기준(DoD)이 명확히 분리되어 병렬 작업 가능.

---

## 0. 오케스트레이션 원칙

- **계약 우선(Contract-first)**: B0(Architect)가 공통 스키마·API 계약·디렉토리 구조를 먼저 확정. 이후 모두 그 위에서 병렬.
- **단일 책임**: 각 에이전트는 자기 디렉토리 밖 코드를 수정하지 않음. 교차 변경이 필요하면 계약을 통해 요청.
- **통합 지점**: 이벤트 스키마(Event Collector), 정규화 스키마(SIEM), 시나리오 YAML, 점수 API가 4대 통합 계약.
- **리뷰 게이트**: 콘텐츠 계층 산출물(문제)은 반드시 QA 에이전트(C-QA) 검수 통과 후 배포.

# 빌드 계층 (Build Agents)

## B0 — Architect / Contract Owner
- **역할**: 전체 아키텍처 총괄, 공통 계약 확정, 통합 관리.
- **담당**: 리포 구조, 이벤트/정규화 스키마, 저장소 인터페이스, docker-compose 뼈대, CI 파이프라인.
- **입력 문서**: 전체 스펙(01~08).
- **산출물**: `shared/` 스키마·인터페이스, compose 파일, 통합 테스트 하니스.
- **DoD**: 나머지 에이전트가 import·연동할 계약이 고정되고 문서화됨.
- **인터페이스**: 모든 에이전트에게 스키마 제공, 변경은 B0만 승인.

## B1 — Digital Twin Engineer
- **역할**: 취약한 디지털 트윈 서비스(위성/발전소/국방망) 구축·유지.
- **담당**: `ground_station/`, `power_plant/`, `defense_network/`, 취약점 구현, `emit_event()` 계측, 구조화 access 로그.
- **입력 문서**: 기존 트윈 코드, 06(탐지 대상), 08(트윈 격리).
- **산출물**: 트윈 서비스 + 취약점 카탈로그 + 패치 토글(Config Service 연동).
- **DoD**: 각 취약점이 vulnerable/patched 전환되고, 공격 시 이벤트·로그 발행.
- **경계**: 취약점 로직만. 점수 판정은 Scoring Engine 소관.

## B2 — Platform Backend Engineer
- **역할**: Event Collector, Scoring Engine, Config Service, Instructor API 등 코어 백엔드.
- **담당**: `event_collector/`, `scoring_engine/`, `config_service/`, `instructor/`.
- **입력 문서**: 04(백엔드 보강 전체), 05(시나리오 러너 연동).
- **산출물**: 이벤트 수집/dedup, 멱등 채점, 복구 판정, dwell 계산, audit log, 패치 무중단 토글, 킬스위치.
- **DoD**: 04번 문서의 DoD 전부 충족.
- **경계**: 탐지 로직은 SIEM(B4) 소관, 여기선 탐지 이벤트를 점수로만 변환.

## B3 — Scenario Engine Engineer
- **역할**: 시나리오 as-code 로더 + Scenario Runner(킬체인 진행 판정).
- **담당**: `scenario/loader.py`, `scenario/runner.py`, 시나리오 YAML 검증기.
- **입력 문서**: 05(시나리오 스키마 전체).
- **산출물**: YAML 로드→초기 취약점 상태 주입, stage 순서 판정, chain_bonus, 진행 상태 API.
- **DoD**: 3종 시나리오가 재현 가능하게 로드·진행·완주 판정.
- **경계**: 문제 내용(YAML)은 콘텐츠 계층이 작성, B3는 실행 엔진만.

## B4 — SIEM Engineer (팀)
- **역할**: 자체 SIEM 구축(수집/정규화/탐지/API/대시보드). 규모상 내부적으로 하위 역할 분담.
- **담당**: `siem/` 전체(01번 문서의 Agent 0~5).
- **입력 문서**: 01(SIEM 빌드 전체), 06(탐지 콘텐츠).
- **산출물**: syslog 수집, ECS-lite 정규화, 규칙 엔진, 검색/알림 API, SIEM 대시보드.
- **DoD**: 4개 소스 수집 green, 20종 룰 탐지, 탐지→Live Fire 점수 연결.
- **하위 분담(팀 내부)**: Ingestion / Normalization / Detection / API / Frontend.

## B5 — Live Fire Dashboard Engineer
- **역할**: 공방 지휘통제 대시보드 + 확장(리플레이/분리뷰/AAR).
- **담당**: `dashboard/` (React).
- **입력 문서**: 02(대시보드), 07(확장 기능).
- **산출물**: Asset Map, Timeline, Score, Patch, Flag, Instructor Console, Replay, 역할별 뷰, AAR.
- **DoD**: 02·07 문서 DoD 충족, 실시간·리플레이·역할뷰 동작.
- **경계**: 백엔드 계약 소비만, 데이터 생성 안 함.

## B6 — Security & Infra / SRE
- **역할**: 안전장치, 격리, 배포, 운영.
- **담당**: 네트워크 격리, 컨테이너 하드닝, CI 시크릿 스캔, 배포 스크립트, 모니터링.
- **입력 문서**: 08(안전장치 전체).
- **산출물**: internal 네트워크, cap_drop/read-only 트윈, 격리 회귀 테스트, 배포 체크리스트 자동화.
- **DoD**: 08 문서 DoD + 배포 전 체크리스트 자동 통과.
- **경계**: 전 서비스에 걸치는 횡단 관심사, 각 팀과 협업.

# 콘텐츠 계층 (Content / 출제 Agents)

> 분야별 공방 문제를 지속적으로 출제. 각 분야 에이전트는 "문제 명세 → 취약 환경 정의 → 정답/플래그 → 채점 기준 → 라이트업(해설)"을 산출.
> 문제 형식 표준은 별도 문서(문제 기획 문서) 참조. Red↔Blue 균형: 각 문제는 **공격 과제(Red)**와 **방어 과제(Blue)**를 함께 정의.

## C0 — Challenge Lead / 문제 총괄
- **역할**: 출제 방향·난이도 곡선·분야 밸런스 관리, 문제 표준 포맷 확정.
- **산출물**: 문제 메타 스키마, 난이도 기준, 분야별 출제 쿼터, 시즌/라운드 구성.
- **DoD**: 모든 분야 에이전트가 따르는 공통 문제 포맷과 채점 규약 확정.

## C1 — Web Security 출제
- **역할**: 웹 취약점 공방 문제.
- **범위**: SQLi/NoSQLi, XSS, SSRF, IDOR, 인증우회, JWT 취약점, 파일업로드, 역직렬화, SSTI, 403 우회, CVE 재현(Grafana 등).
- **산출물**: 취약 웹앱 명세 + 공격 과제 + 탐지/패치 과제 + WAF 룰 작성 과제.

## C2 — Forensics 출제
- **역할**: 디지털 포렌식 문제.
- **범위**: 디스크/메모리 이미지 분석, 파일 카빙, 타임라인 분석, 레지스트리/아티팩트, pcap 분석, 로그 분석, 스테가노그래피, 안티포렌식 탐지.
- **산출물**: 증거 이미지/덤프 + 조사 질문 + 정답 아티팩트 + 채점 기준.

## C3 — Detection Engineering / Blue 출제
- **역할**: 탐지·SIEM·대응 문제(SOC 훈련).
- **범위**: 로그/SIEM 상관분석, 탐지 룰 작성(Sigma), MITRE ATT&CK 매핑, pcap 기반 침해 재구성, 인시던트 대응 플레이북, 위협헌팅.
- **산출물**: 로그/pcap 데이터셋 + 탐지 과제 + 기대 알림 + 룰 채점.

## C4 — AI Security 출제 (전문 분야)
- **역할**: AI/ML 보안 공방 문제.
- **범위**: 적대적 예제(evasion), 모델 추출, 멤버십 추론, 프롬프트 인젝션/탈옥, 데이터 포이즈닝/백도어, ML 파이프라인 취약점, 피싱/악성코드 분류기 회피(Pierazzi 문제공간 프레임워크 응용).
- **산출물**: 취약 ML 시스템/모델 + 공격 과제 + 방어(견고화/탐지) 과제.

## C5 — Reversing / Pwn 출제
- **역할**: 리버스 엔지니어링·바이너리 익스플로잇.
- **범위**: 정적/동적 분석, 난독화 해제, 크랙미, XOR/커스텀 인코딩, 바이너리 취약점(BOF/포맷스트링/힙), 펌웨어 분석.
- **산출물**: 바이너리/펌웨어 + 목표(플래그) + 익스플로잇 기대 + 방어(완화기법) 과제.

## C6 — Network / OT-ICS 출제
- **역할**: 네트워크·산업제어 문제.
- **범위**: 프로토콜 분석, MITM, 피벗팅/측면이동, Modbus/S7 등 OT 프로토콜, SCADA 공격/방어, 방화벽 룰 작성.
- **산출물**: 네트워크 토폴로지/트래픽 + 공격 경로 + 탐지/차단 과제.

## C-QA — 문제 검수 / 밸런스
- **역할**: 모든 문제의 재현성·정답 유일성·난이도·안전성 검수.
- **체크**: 의도된 해법으로 풀리는가, 비의도 해법(unintended)은 없는가, 플래그가 확정적인가, 실데이터/실취약점 유출 없는가, 채점 자동화가 동작하는가.
- **DoD**: 검수 통과한 문제만 배포 큐로.

## 통합 흐름 요약

```
B0 계약 확정
   ├─ B1 트윈 ─┐
   ├─ B2 코어 ─┤
   ├─ B3 시나리오┤─▶ 통합(이벤트/점수/시나리오 계약)
   ├─ B4 SIEM ─┤
   ├─ B5 대시보드┤
   └─ B6 안전 ──┘
콘텐츠:
C0 표준 ─▶ C1~C6 분야별 출제 ─▶ C-QA 검수 ─▶ 배포
                (B3 시나리오 엔진 / B1 트윈 위에 문제 탑재)
```

## 추천 진행 순서

1. **B0 계약** → 전체의 전제.
2. **B1·B2·B6 병렬**(트윈·코어·안전) → 플랫폼 최소 동작.
3. **B3·B4 병렬**(시나리오·SIEM) → 공방 루프 완성.
4. **B5**(대시보드) → 가시화.
5. **C0 표준 확정 후 C1~C6 병렬 출제** → C-QA 검수 → 배포.

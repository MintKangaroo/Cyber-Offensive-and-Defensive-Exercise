# 대시보드 확장 스펙 — Claude Code 빌드 프롬프트

> 로드맵 ★★ "리플레이(AAR)" + "Red/Blue 분리뷰 + 관전자 뷰" + "자동 리포트" 구현 사양.
> Live Fire Dashboard(프롬프트 02)에 얹는 확장 기능.

---

## 1. 리플레이 / After-Action Review (★★)

**목적**: 훈련 종료 후 이벤트 타임라인을 배속 재생해 디브리핑. 가장 교육 효과 큰 기능 중 하나.

**구현**:
- Event Collector에 이미 모든 이벤트가 timestamp와 함께 저장됨 → 리플레이는 이 데이터의 시간축 재생.
- `GET /replay/events?scenario_id=&from=&to=` → 시간순 이벤트 전체.
- 프론트 Replay 모드:
  - 재생/일시정지/배속(1x/2x/4x/8x), 타임라인 스크러버(특정 시점으로 점프)
  - 재생 중 Asset Map 상태 전이, 점수 증가, 알림 발생이 그 시점 그대로 재현
  - "이 순간에 무슨 일이" — 특정 이벤트 클릭 시 전후 맥락(상관 이벤트) 하이라이트
- 실시간 대시보드와 동일 컴포넌트 재사용, 데이터 소스만 라이브 WS ↔ 리플레이 스트림으로 스왑.

## 2. Red / Blue / 관전자 분리 뷰 (★★)

**목적**: 정보 비대칭으로 몰입감·현실성 향상. Red는 방어 상태를 모르고, Blue는 공격 계획을 모름.

**뷰별 노출 범위**:

| 요소 | Red 뷰 | Blue 뷰 | 관전자/교관 |
|---|---|---|---|
| 자기 팀 진행 킬체인 | O | O | O |
| 상대 팀 상세 활동 | X | X | O |
| Asset Map 상태 | 자기가 침해한 것만 | 전체 방어 상태 | 전체 |
| 탐지 알림 | X (탐지됐는지 모름) | O | O |
| 패치 현황 | X | O | O |
| 플래그 상태 | 자기가 획득한 것 | 유출 여부 | 전체 |
| 점수 | 자기 팀 총점만 | 자기 팀 총점만 | 전체 대비 |
| Instructor Console | X | X | O(교관만) |

**구현**:
- 로그인 역할(red/blue/observer/instructor) 기반 뷰 라우팅 + API 응답 필터링(백엔드에서 역할별 스코프 적용, 프론트만 숨기면 안 됨 — 치팅 방지).
- 관전자 뷰는 "중계방송" 성격: 양 팀 활동 + 실시간 점수 + 하이라이트.

## 3. 자동 리포트 (After-Action Report PDF) (★★)

**목적**: 훈련 종료 시 팀별 성과를 자동 집계한 PDF. 제안서 13장 Phase 6.

**리포트 구성**:
1. **요약**: 시나리오명, 참가팀, 기간, 최종 점수(Red vs Blue).
2. **타임라인 요약**: 주요 이벤트(초기침투/목표달성/최초탐지/복구) 시각.
3. **Red 성과**: 달성 킬체인 단계, 획득 플래그, 은신 시간(미탐지 유지), 미달성 목표.
4. **Blue 성과**:
   - **MTTD**(평균 탐지시간): 공격 발생 → 최초 탐지까지.
   - **MTTR**(평균 복구시간): 침해 → 복구까지.
   - 탐지율(발생 공격 중 탐지한 비율), 차단율, 오탐률.
5. **ATT&CK 히트맵**: 이번 훈련에서 사용된 공격 기술 × 탐지 여부 매트릭스.
6. **타임라인 차트**: 시간대별 점수 추이, 이벤트 밀도.
7. **개선 권고**: 미탐지된 공격 기술, 느린 대응 구간 지적(룰 기반 자동 생성 코멘트).

**구현**:
- `GET /report/aar?scenario_id=` → 집계 JSON.
- PDF 생성은 서버측(예: WeasyPrint/ReportLab) 또는 프론트 print-to-PDF. 지표 계산은 반드시 서버(신뢰성).
- 지표 계산 근거가 되는 이벤트는 백엔드 3절(dwell time, matched_event_id 연결)에 의존 → 그 기능이 선행돼야 정확한 MTTD/MTTR 산출 가능.

## 4. 사운드/알람 (★)

- critical 알림(sev4) 발생 시 오디오 큐. 워룸 몰입감.
- 반드시 토글 가능 + 기본 off(예상치 못한 소리 방지). 브라우저 자동재생 정책 고려(사용자 상호작용 후 활성).

---

## 5. 개발 순서 & DoD

- **M1**: 리플레이(1절) — 기존 저장 이벤트만으로 구현 가능, 의존성 적음.
- **M2**: 역할별 분리 뷰(2절) — 백엔드 역할 스코프 필요.
- **M3**: AAR 리포트(3절) — 백엔드 dwell/matched 지표 선행.
- **M4**: 사운드(4절).

**DoD**: 종료된 훈련을 4x로 리플레이하며 점수/자산 상태가 그 시점대로 재현되고, 역할별로 다른 정보가 보이며, AAR PDF에 MTTD/MTTR/ATT&CK 히트맵이 정확히 산출됨.

# PWN-021 방어 — 힙 선형 오버플로우(인접 청크 침범)

## 취약점
각 작업(task)은 힙에 `{char data[24]; void(*handler)(void);}`(32바이트) 구조로 순차 할당된다.
`edit` 의 쓰기 길이가 `data[24]` 영역을 넘어도 검증되지 않는다. 순차 할당은 힙에서 인접하게
배치되므로, `task0.data` 시작점에서 80바이트를 쓰면 `task0.handler`(8B) → `task1` 청크 헤더(16B)
→ `task1.data`(24B) 를 지나 **`task1.handler` 를 덮어쓸 수 있다**. 절대 힙 주소를 몰라도(leak 불필요)
순수 상대 오프셋만으로 인접 청크의 함수 포인터를 임의 주소로 바꿀 수 있다.

## 탐지 (Blue)
- 고정 크기 버퍼(`data[24]`)에 길이 검증 없이 쓰는 `read`/`memcpy` 호출을 감사.
- 함수 포인터가 사용자 제어 버퍼와 같은 힙 청크(또는 인접 청크)에 위치하는지 점검.

## 패치
쓰기 길이를 데이터 영역 크기로 제한해 오버플로우를 제거한다.

```c
// 취약: n 이 sizeof(data) 를 넘어도 그대로 read
if (n > 0x200) { ... }
read(0, t->data, n);
// 안전: n 을 데이터 영역 크기로 제한
if (n > sizeof(t->data)) n = sizeof(t->data);
read(0, t->data, n);
```

- **경계 검증**: 쓰기 길이를 필드 크기(`sizeof(data)`)로 제한.
- **레이아웃 분리**: 함수 포인터를 사용자 버퍼와 다른 메모리 영역(별도 배열/스택)에 두어 인접 침범 자체를 무력화.
- **가드/카나리**: 힙 청크 사이에 가드 값을 두고 손상 여부를 free/조회 시 검증(예: 힙 카나리, `_FORTIFY_SOURCE`).

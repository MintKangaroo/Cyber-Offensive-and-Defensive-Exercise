# PWN-015 방어 — off-by-one NULL 바이트(함수 포인터 LSB 변조)

## 취약점
`read_name()` 의 스택 구조체 `{ char name[64]; void (*action)(void); }` 에서 입력을 64바이트까지
채운 뒤 종단 널 `name[n]='\0'` 을 쓴다. `n` 이 64가 되면 `name[64]` 은 버퍼를 정확히 한 바이트
넘어 인접한 `action` 포인터의 **최하위 바이트를 0** 으로 만든다(single NULL overflow).

`action` 은 원래 `benign()`(예: `0x401216`)을 가리키는데, `win()` 이 256바이트 정렬(`0x401200`)이라
같은 256블록에 있다. LSB 를 0 으로 만들면 `action == win()` 이 되어 이어지는 `action()` 호출이
`win() = system("cat /flag")` 로 흐른다. no-PIE 라 함수 주소가 고정이므로 **결정적**(스택 ASLR 무관).

## 탐지 (Blue)
- 버퍼 크기와 종단 널 인덱스의 경계를 감사 — `buf[n]=0` 에서 `n` 이 `sizeof(buf)` 에 도달할 수 있으면 off-by-one.
- 버퍼 바로 뒤에 함수 포인터/길이/사이즈 등 민감 필드를 인접 배치하지 않았는지 점검.

## 패치
경계를 한 칸 줄여 종단 널이 항상 버퍼 안에 머물게 하고, 포인터 무결성 완화를 병행한다.

```c
// 취약: n 이 64까지 → name[64] 가 다음 필드(LSB) 침범
while (n < 64 && ...) name[n++] = c;
name[n] = '\0';
// 안전: 종단 널 자리를 남겨 n 을 63까지만
while (n < 63 && ...) name[n++] = c;
name[n] = '\0';           // 최대 name[63] — 버퍼 내부
```

- **경계 축소**: 종단 널을 위한 한 바이트를 항상 확보(`n < sizeof-1`).
- **스택 카나리**(`-fstack-protector-all`): 인접 필드 변조 탐지에 도움.
- **레이아웃 분리**: 함수 포인터를 사용자 버퍼와 인접시키지 말고, 가능하면 상수/인덱스 기반 디스패치 사용.
- **PIE/ASLR**: 코드 주소를 무작위화해 LSB 정렬 트릭(고정 win 주소)을 무력화.

# CRY-017 방어 — Paillier 준동형 가변성(malleability)

## 취약점
Paillier 는 덧셈 준동형 암호다: `E(m1)·E(m2) mod n^2 = E(m1+m2)`, `E(m)·g^k mod n^2 = E(m+k)`.
서버가 관리자 크레딧 암호문 `c_V = E(V)` 를 공개하고, `/api/redeem` 이 복호값이 `V + delta` 이면
접근을 허가한다. 준동형 성질 때문에 개인키·`V` 를 몰라도

```
c' = c_V · g^delta mod n^2 = E(V + delta)
```

를 만들어 제출하면 복호값이 정확히 `V + delta` 가 되어 인가를 통과한다. 무결성(비가변성) 없는 준동형
암호문을 신뢰하면 관련 평문을 자유롭게 위조할 수 있다.

## 탐지 (Blue)
- 준동형 암호문을 그대로 신뢰해 권한 판단에 쓰는지 감사 — 가변성으로 위조 가능.
- 제출된 암호문의 출처/무결성(서명·태그·NIZK)을 검증하는지 점검.

## 패치
`PATCH_CRY_017=true` — 서버가 발급한 암호문에 **HMAC 무결성 태그**를 붙이고, redeem 이 유효한 태그가
있는 암호문만 수락한다(서버만 태그 생성 가능 → 위조 암호문 거부).

```python
# 취약: 암호문을 그대로 복호·신뢰
m = decrypt(c); grant if m == V + delta
# 안전: 무결성 태그 검증(위조 차단) — 또는 비가변(NM-CCA) 스킴
if not verify_tag(c, tag): reject
```

- **무결성/인증**: 준동형 암호문에 서버 HMAC/서명을 붙이거나, 제출 암호문에 대한 **영지식 증명(NIZK)**
  으로 well-formed 임을 강제.
- **비가변 스킴**: 가변성이 불필요하면 NM-CCA 안전한 스킴(예: 인증 포함)으로 전환.
- 준동형 연산은 서버 내부에서만 수행하고, 외부 제출 암호문을 권한 결정에 직접 쓰지 않는다.

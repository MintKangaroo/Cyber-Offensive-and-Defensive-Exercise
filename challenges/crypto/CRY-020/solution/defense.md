# CRY-020 방어 — RSA e=3 관련 메시지(Franklin-Reiter)

## 취약점
동일한 평문 `M` 을 알려진 선형 관계로 두 번 암호화하면(여기서는 프레임 카운터 때문에
`m2 = m1 + delta`, `delta` 공개), 작은 공개지수 `e=3` 에서 두 다항식이 공통근 `x=m1` 을 갖는다:

```
g1(x) = x^3 - c1        (mod N)
g2(x) = (x + delta)^3 - c2   (mod N)
gcd(g1, g2)  →  선형 인수 (a·x + b)  →  m1 = -b·a^-1 mod N
```

개인키·인수분해 없이 다항식 GCD(유클리드) 만으로 평문이 복구된다(Franklin, Reiter 1996).
공격 비용은 다항식 차수(=e) 에 좌우되며 `e=3` 에서는 즉시 성립한다.

## 탐지 (Blue)
- 같은 명령/평문이 알려진 대수 관계(선형 등)로 반복 암호화되는지 점검.
- 작은 공개지수(e=3) 사용, 패딩 없는 raw RSA(textbook RSA) 사용 여부 감사.

## 패치
`PATCH_CRY_020=true` — 프레임마다 **독립 무작위 패딩**을 적용해 두 평문 사이의 알려진 대수
관계를 제거한다.

```python
# 취약: 관련 메시지(선형 관계 노출) + textbook RSA
c1 = pow(m1, 3, N)
c2 = pow(m1 + delta, 3, N)   # 관계 m2 = m1 + delta 공개

# 안전: 프레임마다 무작위 OAEP 패딩 → 두 평문 사이 대수 관계 소멸
c1 = pow(oaep_pad(M, rand1), e, N)
c2 = pow(oaep_pad(M, rand2), e, N)
```

- **RSA-OAEP** 등 무작위 패딩 사용(프레임마다 독립 난수) — 같은 평문이라도 관계 노출 없음.
- **큰 공개지수** `e=65537` 사용으로 저지수 특성 제거.
- **평문 재전송 금지**: 동일 명령을 관련 형태로 반복 전송하지 않도록 프로토콜 설계
  (프레임 카운터를 평문에 직접 더하지 말고 인증된 헤더로 분리).

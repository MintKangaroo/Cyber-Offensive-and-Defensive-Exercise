# CRY-019 방어 — 약한 RNG 공유 소수(배치 GCD)

## 취약점
엔트로피가 부족한 RNG 로 대량의 RSA 키를 생성하면, 서로 다른 두 기기의 모듈러스가 소수 하나를
공유할 수 있다. 공개된 여러 모듈러스 `N_i` 에 대해 **쌍별 GCD** 를 구하면 공유 소수 `p` 가 드러난다:

```
gcd(N_a, N_b) = p  (두 기기가 p 를 공유하면)
→ q_a = N_a / p,  d = e^-1 mod (p-1)(q_a-1)  → 복호
```

2012년 "Mining your Ps and Qs" 연구가 인터넷 전수 스캔에서 이 결함으로 수만 개 키를 인수분해했다.
전체 배치는 GCD 트리로 `O(n log^2 n)` 에 처리된다.

## 탐지 (Blue)
- 키 생성 시 RNG 시드/엔트로피 소스가 충분한지(부팅 초기 엔트로피 부족 등) 감사.
- 발급된 공개키 집합에 대해 주기적으로 배치 GCD 를 돌려 공유 소수를 자체 점검.

## 패치
`PATCH_CRY_019=true` — 모든 소수를 독립적인 고엔트로피 소스로 생성해 공유 소수를 제거한다.

```python
# 취약: 엔트로피 부족으로 소수 공유
p = weak_rng_prime()      # 여러 기기가 같은 값
# 안전: 충분한 엔트로피로 독립 생성
p = secrets_prime()       # OS CSPRNG, 기기마다 유일
```

- **고엔트로피 CSPRNG**: `/dev/urandom` 등 충분히 시드된 소스 사용, 부팅 초기 엔트로피 확보 후 키 생성.
- **키 유일성 검증**: 발급 파이프라인에서 배치 GCD 로 공유 소수 여부를 사전 점검.
- **하드웨어 RNG/키 주입**: 기기 자체 생성 대신 안전한 프로비저닝으로 키를 주입.

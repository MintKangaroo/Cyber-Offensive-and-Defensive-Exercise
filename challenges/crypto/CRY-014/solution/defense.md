# CRY-014 방어 — RSA PKCS#1 v1.5 패딩 오라클(Bleichenbacher)

## 취약점
복호 시 PKCS#1 v1.5 패딩(`00 02 ...`) 유효성을 공격자에게 노출하면, 이 **패딩 오라클** 하나만으로
Bleichenbacher(1998) 적응적 선택암호문 공격이 성립한다. 공격자는 `c' = c0·s^e mod n` 형태의
암호문을 반복 질의하며 평문이 담긴 구간 `[2B, 3B)` 를 점점 좁혀 개인키 없이 `c0` 의 평문을 복구한다.

```
오라클: PKCS 패딩 적합(00 02) 이면 참
→ s 를 조정해 c0·s^e 의 복호가 적합해지는 s 를 탐색(질의)
→ 가능한 평문 구간을 이분적으로 좁혀 유일값으로 수렴
```

512비트 키에서도 수천 회 질의로 평문(세션 토큰)이 복구된다.

## 탐지 (Blue)
- 복호 API 가 패딩 오류와 다른 오류를 **구분 가능한 형태**(상태 코드/메시지/응답시간)로 노출하는지 감사.
- PKCS#1 v1.5 복호를 쓰는 엔드포인트 전수 조사 — 오라클이 될 수 있는 모든 관측 채널 점검.

## 패치
`PATCH_CRY_014=true` — 패딩 유효성을 노출하지 않고(성공/실패 응답을 동일하게), 근본적으로는
패딩 오라클에 강한 스킴으로 전환한다.

```python
# 취약: 패딩 유효성을 그대로 반환
return {"padding_ok": m[0]==0 and m[1]==2}
# 안전: 유효성을 노출하지 않음(동일 응답) — 또는 RSA-OAEP 사용
return {"status": "processed"}
```

- **RSA-OAEP(PKCS#1 v2)**: 패딩 오라클 공격에 견고한 표준 패딩으로 교체.
- **오라클 제거**: 성공/실패·오류 메시지·응답 시간을 구분 불가능하게(상수 시간, 동일 응답).
- **키 캡슐화(KEM)**: RSA-KEM 등 오라클이 성립하지 않는 구조 채택.

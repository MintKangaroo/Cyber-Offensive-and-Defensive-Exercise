# WEB-007 Writeup (훈련 후 공개)

**근본원인**: 업로드 필터가 파일의 실제 확장자/내용이 아니라 **클라이언트가 보낸
`content_type`만 신뢰**했다. content_type은 요청자가 임의로 조작할 수 있으므로 검증 근거가 될 수 없다.

**공격**:
1. 업로드가 "이미지만 허용"한다는 근거가 무엇인지 확인 → content_type 필드.
2. `content_type=image/png`로 두고 `filename=avatar.py`로 요청.
3. 필터는 통과하고, 서버는 확장자를 보고 스크립트로 처리 → 승인 코드 노출.

**방어**: content_type 대신 **실제 확장자 화이트리스트**로 검증하고(더 나아가 매직바이트 확인),
업로드 파일은 실행 불가 경로에 랜덤 파일명으로 저장한다.

**교훈**: "클라이언트가 보낸 메타데이터는 검증이 아니다." 신뢰 경계 밖에서 온 값
(content_type, filename, 확장자 문자열)은 전부 공격자 통제 하에 있다고 가정하고 서버가 직접 판정해야 한다.

# WEB-002 Writeup (훈련 후 공개)

**근본원인**: JWT 서명 검증에서 `alg` 화이트리스트가 없어 `alg=none`을 그대로 수용했고,
대칭키(`supersecret123`)가 하드코딩되어 있었다.

**공격**: 헤더의 `alg`를 `none`으로 바꾸면 서명 검증 자체가 스킵된다. 또는 알려진/유출된
약한 키로 정상 서명한 토큰을 만들 수 있다.

**방어**: `jwt.decode(token, secret, algorithms=["HS256"])`처럼 알고리즘을 명시적으로
화이트리스트에 고정하고, 비대칭키(RS256) 전환과 시크릿 로테이션을 권장한다.

**교훈**: "검증하지 않는 서명은 서명이 아니다."
